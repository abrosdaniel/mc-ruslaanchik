# Работа над сборкой Ruslaanchik

Здесь описано, как менять состав сборки, обновлять инструкцию и готовить релизы.

## 🛠️ Внесение изменений

Перед началом работы получите последние изменения из `main`: Action может добавлять собственные коммиты с обновлением таблицы модов.

1. Измените нужные файлы в репозитории.
2. Проверьте ссылки, версии модов и запуск сборки с изменённым составом.
3. Сохраните изменения коммитом. Если у вас нет доступа на запись, предложите их через pull request; при наличии доступа отправьте изменения в `main`.

Версию сборки повышает владелец при подготовке выпуска. Для обычного редактирования файлов менять её не нужно.

## 📦 Файлы сборки

Состав сборки задаётся в [manifest.json](manifest.json). В массиве `files` укажите название мода, его версию, путь в сборке и прямую HTTPS-ссылку на файл:

```json
{
  "name": "Example Mod",
  "version": "1.0.0",
  "path": "mods/example-1.0.0.jar",
  "url": "https://cdn.modrinth.com/data/PROJECT/versions/VERSION/example-1.0.0.jar"
}
```

- Моды: `mods/имя.jar`.
- Текстурпаки: `resourcepacks/имя.zip`.
- Шейдеры: `shaderpacks/имя.zip`.
- Настройки для клиента: папка `config` в репозитории. Общие настройки, используемые клиентом, тоже допустимы; серверные конфиги и личные данные игроков добавлять не нужно.

При обновлении мода изменяйте `url`, `path` и его поле `version` вместе. При необходимости обновляйте `name`. Версия внутри записи мода и версия всей сборки в начале manifest — разные поля.

Все файлы из списка и папка `config` включаются в архивы.

## 🧩 Таблица модов в README

При изменении `manifest.json` или README Action формирует таблицу модов и сохраняет README отдельным коммитом. Повышать версию сборки для этого не нужно. Таблица показывает текущий состав manifest, который может отличаться от последнего релиза.

Для Modrinth данные берутся автоматически, если соответствующие поля не заданы в manifest. Указанные вручную `name`, `version`, `author` и `page` имеют приоритет. Поэтому уже заполненные названия и версии нужно поддерживать вручную.

По умолчанию мод обязательный. Добавьте `"required": false`, чтобы перенести его в необязательные. Это влияет только на таблицу: в архивы по-прежнему включаются все файлы.

Для мода с другого сайта обязательно укажите `name`, `version` и `author`:

```json
{
  "name": "Example Mod",
  "version": "1.0.0",
  "path": "mods/example-1.0.0.jar",
  "url": "https://example.com/downloads/example-1.0.0.jar",
  "author": "Автор",
  "page": "https://example.com/mod",
  "required": false
}
```

Поле `page` необязательно: без него используется ссылка на скачивание. В таблицу попадают только файлы из `mods/`.

Содержимое таблицы редактировать вручную не нужно. Сохраняйте границы блока `<div id="mod-list">` и `<a name="mod-list-end"></a>` в README. Остальную инструкцию Action не меняет.

После автоматического коммита получите изменения с GitHub перед следующей отправкой своих коммитов.

## 🚀 Публикация релиза владельцем

Когда изменения проверены и сборка готова:

1. Обновите описание выпуска в [RELEASE.md](RELEASE.md).
2. Измените верхнее поле `version` в `manifest.json`, например с `1.0.0` на `1.0.1`.
3. Сделайте commit и push в `main`.

GitHub Actions проверит версию. Если она уже опубликована, новый релиз не создаётся. Для новой версии Action соберёт архивы и опубликует релиз с описанием из `RELEASE.md`. Опубликованные релизы при обычных push не перезаписываются.

Файл `.mrpack` создаётся только тогда, когда все ссылки ведут на `cdn.modrinth.com`, включая адрес после перенаправления. Иначе выпускаются только ZIP-архивы и контрольные суммы.
