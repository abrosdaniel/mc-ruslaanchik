# Поддержка проекта Ruslaanchik

Проект использует контракт текущего AntHub v1 (`1.0.0-alpha.1`).

## Структура

- `anthub.json` — стабильный ID `ruslaanchik`, версия сборки, Minecraft/NeoForge, сервер и оформление.
- `pack/client.json` — клиентские компоненты, фиксированные версии, зависимости и файлы.
- `config/` — исходные настройки, явно перечисленные через `repositoryPath`.
- `assets/icon.png` — иконка в подписанном снимке.
- `content/` — новости, условия доступа и история изменений.
- `schemas/v1/` и `tooling/` — копия контракта и инструментов из локального проекта AntHub.
- `keys/project.pub.json` — публичный ключ (создаётся при первом выпуске).
- `channels/` — подписанные указатели, публикуемые workflow.

## Проверка

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r tooling/requirements.txt
python tooling/anthub.py validate .
python tooling/update_mod_list.py
```

`Validate project` выполняется при push и pull request. Список в README строится из `pack/client.json`, без обращения к Modrinth.

## Изменение состава

Для каждого мода задайте стабильный `id`, `kind` (`required`, `recommended`, `optional`), зависимости и конфликты по ID компонентов. В `files` используйте прямой HTTPS URL конкретной версии и `policy: enforce`. Не используйте latest или страницы загрузки.

Настройки прикрепляются к соответствующему компоненту и используют `policy: preserve`. Файлы NeoForge находятся в `shared-config`. При изменении локального файла обновите его SHA-256 в `pack/client.json`; хеш проверяется при сборке релиза. Не добавляйте пользовательские пароли, `authlogic`, миры, карты, `servers.dat` или личные настройки в проект.

Обновите `pack.version` в `anthub.json`, `content/changelog.md` и список в README. После первого релиза версия должна увеличиваться. Старый `manifest.json` заменён двумя манифестами AntHub; архивы Prism/mrpack больше не собираются.

## Первый выпуск

1. Создайте постоянный ключ подписи:

   ```sh
   python tooling/anthub.py keygen --private project.private.pem --public keys/project.pub.json
   ```

2. Сохраните приватный ключ в надёжном месте и добавьте его содержимое в GitHub Actions secret **ANTHUB_SIGNING_KEY**. Файл `*.private.pem` исключён из Git. Не меняйте ключ после первого выпуска без отдельной миграции доверия.
3. Закоммитьте публичный ключ и файлы проекта в основной ветке GitHub. Приватный ключ не публикуйте.
4. Запустите **Publish pack** из основной ветки, выберите `stable` и `sequence: 1` для первого выпуска. Для каждого следующего выпуска увеличивайте sequence и версию сборки.
5. Workflow скачает файлы, вычислит SHA-256 и размер, подпишет lock, проверит подпись, опубликует `pack-v<version>` и обновит `channels/stable.json` вместе с подписью.

До этих действий репозиторий подготовлен, но ещё не устанавливается через AntHub. Постоянный ключ и секрет автоматически при миграции не создавались.

При прерывании выпуска сначала проверьте draft release и channel: автоматическое восстановление публикации имеет ограничения. Не перезаписывайте уже используемые релизы и не понижайте sequence.

## Сервер

Смотрите [pack/server.md](pack/server.md). AntHub управляет клиентской сборкой; серверные моды администратор устанавливает отдельно.

## Известное ограничение исходного состава

У закреплённого Iris `1.8.14-beta.1+1.21.1-neoforge` внутри JAR указан диапазон Minecraft `[1.21,1.21.1)`, исключающий 1.21.1. Его версия сохранена при переносе. Перед выпуском проверьте запуск с Iris; при ошибке отключите этот необязательный компонент или отдельно подберите исправленную версию. Успешная проверка формата и подписи не проверяет запуск Minecraft.

Зависимости компонентов перенесены из метаданных закреплённых версий Modrinth. У WaterFrames использованы зависимости из NeoForge JAR (CreativeCore и WaterMedia); у LambDynamicLights NeoForge runtime встроен в JAR. Fabric-зависимости и конфликты с отсутствующими в сборке компонентами в граф не добавлялись. Iris выбирается вместе с Sodium.
