# Ruslaanchik

![Ruslaanchik](assets/icon.png)

Приватный Minecraft-сервер стримера Ruslaanchik. **Minecraft 1.21.1 · NeoForge 21.1.250 · Java 21.**

Сервер: `mc-ruslaanchik.ebash.id`.

[Twitch](https://www.twitch.tv/ruslaanchik) · [Telegram](https://t.me/Ruslaanchik_gg) · [DonationAlerts](https://www.donationalerts.com/r/ruslaanchik)

## Установка для игроков

1. Создайте отдельный профиль Minecraft с указанными NeoForge и Java.
2. Установите совместимый JAR [AntHub](https://github.com/abrosdaniel/anthub) в `mods` и запустите игру.
3. В **AntHub → Проекты** добавьте `https://github.com/abrosdaniel/mc-ruslaanchik`.
4. Выберите компоненты сборки, подтвердите установку и дождитесь подготовки. Закройте игру по подсказке AntHub, дождитесь применения файлов и запустите профиль снова.
5. Подключитесь к серверу Ruslaanchik. Для доступа сообщите администрации свой игровой ник.

Установка доступна после первого подписанного релиза. Точный состав: [pack/client.json](pack/client.json). Новости, условия доступа и изменения находятся в [content/](content/). Не передавайте другим данные AuthLogic.

## Структура репозитория

- `anthub.json` — описание проекта, версия сборки и сервер.
- `pack/client.json` — моды, зависимости и правила установки файлов.
- `files/config/` — исходные настройки; в игре они устанавливаются в `config/` с сохранением пользовательских изменений.
- `assets/` — оформление; `content/` — новости и правила.
- `tooling/`, `schemas/`, `.github/workflows/` — инструменты и контракт актуального шаблона AntHub.
- [pack/server.md](pack/server.md) — отдельная настройка серверной интеграции.

Исходники, ключ проверки, канал обновлений и релизы размещаются в GitHub.

## Однократная настройка

1. Репозиторий уже собран из актуального шаблона AntHub и включает `tooling/`, `schemas/` и `.github/workflows/`.
2. Проверьте данные Ruslaanchik в `anthub.json` и компоненты в `pack/client.json`. При изменении настроек в `files/config/` обновляйте SHA-256 соответствующего файла в манифесте. Серверные моды устанавливаются отдельно вручную.
3. Установите зависимости и создайте ключ:

```sh
python -m pip install -r tooling/requirements.txt
python tooling/anthub.py keygen --private project.private.pem --public keys/project.pub.json
```

4. В GitHub откройте **Settings → Secrets and variables → Actions → New repository secret**. Имя: `ANTHUB_SIGNING_KEY`; значение: полное содержимое `project.private.pem`, включая строки BEGIN/END. Приватный файл не добавляйте в Git; сохраните резервную копию отдельно. Публичный `keys/project.pub.json` добавьте в коммит.
5. Actions должны быть включены, а правила ветки должны разрешать workflow записывать `channels/` с помощью `GITHUB_TOKEN`. Workflow запрашивает `contents: write`; если правила организации это запрещают, публикация завершится ошибкой, а не обойдёт защиту.

## Автоматический выпуск

**Измените `pack.version` в `anthub.json`, сделайте commit и push в основную ветку репозитория.** Ручной запуск Action и ввод sequence не нужны.

Пример изменения:

```json
"pack": {
  "version": "1.0.1",
  "manifest": "pack/client.json"
}
```

Action **Publish pack** сравнивает версию до и после push. Если она изменилась, он проверяет проект, автоматически увеличивает sequence, подписывает lock, создаёт GitHub Release `pack-v1.0.1` и публикует `channels/stable.json` вместе с подписью. Канал обновляется последним, после проверки загруженных файлов. Первая публикация использует sequence 1.

- Push с неизменной версией не выпускает релиз, даже если изменились моды, конфиги или README. Для доставки изменений игрокам поднимите версию.
- При первом push нового репозитория предыдущей версии нет: текущая версия выпускается автоматически. Ключ и secret должны быть настроены заранее.
- Ветки разработки и pull requests проходят Validate project; релизы публикуются только из основной ветки, независимо от того, называется она main или master.
- Автоматический коммит файлов канала не меняет версию и не создаёт повторный релиз.
- Уже опубликованная текущая версия пропускается. Не переиспользуйте старые номера и не меняйте файлы существующих релизов.
- Если запуск упал, исправьте причину и используйте **Re-run failed jobs** в Actions. Частично выпущенный релиз не перезаписывается: его файлы должны совпасть. При изменении исходников используйте новую версию.
- Одновременные публикации сериализованы. Если основная ветка уже содержит другую версию, устаревший запуск не обновит канал.

После успешного Action добавьте в AntHub обычный URL этого GitHub-репозитория. Отдельный сайт, ручное создание channels и добавление в центральный Registry не требуются.

## Локальная проверка

```sh
python tooling/anthub.py validate .
```

Новости и правила находятся в `content/`; branding — в `assets/`. Все серверы проекта используют общий клиентский набор.

## Совместимость исходной сборки

Версии модов сохранены. Закреплённый Iris `1.8.14-beta.1+1.21.1-neoforge` объявляет внутри JAR диапазон Minecraft `[1.21,1.21.1)`, исключающий 1.21.1. Перед выпуском проверьте запуск с Iris; при ошибке отключите необязательный компонент или подберите исправленную версию. Валидация проекта не заменяет проверку запуска игры.
