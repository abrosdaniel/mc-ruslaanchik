# Ruslaanchik

![Ruslaanchik](assets/icon.png)

Приватный Minecraft-сервер стримера Ruslaanchik. **Minecraft 1.21.1 · NeoForge 21.1.250 · Java 21.**

Сервер: `mc-ruslaanchik.ebash.id`.

[Twitch](https://www.twitch.tv/ruslaanchik) · [Telegram](https://t.me/Ruslaanchik_gg) · [DonationAlerts](https://www.donationalerts.com/r/ruslaanchik)

## Установка для игроков

1. Создайте отдельный профиль Minecraft с указанными NeoForge и Java.
2. Установите совместимый JAR [AntHub](https://github.com/abrosdaniel/anthub) в `mods` и запустите игру.
3. В **AntHub → Проекты** добавьте `https://github.com/abrosdaniel/mc-ruslaanchik`.
4. Выберите компоненты сборки, подтвердите установку и дождитесь подготовки. Закройте игру по подсказке AntHub, дождитесь применения файлов и запустите профиль снова.
5. Подключитесь к серверу Ruslaanchik. Для доступа сообщите администрации свой игровой ник.

Установка доступна после первого релиза. Точный состав: [pack/client.json](pack/client.json). Новости, условия доступа и изменения находятся в [content/](content/). Не передавайте другим данные AuthLogic.

## Структура репозитория

- `anthub.json` — описание проекта, версия сборки и сервер.
- `pack/client.json` — моды, зависимости и правила установки файлов.
- `files/config/` — исходные настройки; в игре они устанавливаются в `config/` с сохранением пользовательских изменений.
- `assets/` — оформление; `content/` — новости и правила.
- `tooling/`, `schemas/`, `.github/workflows/` — инструменты и контракт актуального шаблона AntHub.
- [pack/server.md](pack/server.md) — отдельная настройка серверной интеграции.

Одна основная версия сборки. Всё размещается в GitHub. Ключи подписи, пользовательские secrets и отдельный сайт не нужны.

## Начать

1. Репозиторий уже подготовлен по актуальному шаблону, включая `.github/`, `tooling/` и `schemas/`.
2. Заполните `anthub.json`: `pack.version`, Minecraft/NeoForge и единственный `server.address`. Файлы сборки настройте в `pack/client.json` — точные HTTPS URL или `repositoryPath`.
3. Сделайте commit и push в основную ветку. Action **Publish pack** создаст первый релиз автоматически. Для fork при необходимости откройте вкладку Actions и включите workflows кнопкой GitHub.
4. После успешного Action добавьте обычную ссылку на свой GitHub-репозиторий в AntHub.

Адрес текущего репозитория определяется автоматически. При fork канал исходного проекта не считается вашим опубликованным релизом. `GITHUB_TOKEN` выдаётся GitHub автоматически; создавать или копировать его не нужно. Workflow запрашивает право `contents: write`. Если организация защищает ветку от записи workflows, её правила должны разрешать публикацию `channels/`.

## Обновление сборки

Измените файлы и **`pack.version` в `anthub.json`**, например с `1.0.0` на `1.0.1`, затем commit и push.

Action проверяет проект, вычисляет SHA-256, создаёт GitHub Release `pack-v1.0.1` и обновляет указатель основной версии. Номер sequence рассчитывается автоматически. Вручную создавать release, channels или запускать workflow не нужно.

- Первый выпуск создаётся при push, если в этом репозитории ещё нет своего опубликованного канала.
- После первого выпуска push без изменения версии ничего не публикует.
- Выпуск работает только в основной ветке; pull requests проверяются без публикации.
- Коммит канала не создаёт повторный релиз.
- Для каждого обновления используйте новый, возрастающий номер версии. Не переиспользуйте старые номера.
- При сбое откройте Actions и нажмите **Re-run failed jobs**. Опубликованные файлы не перезаписываются; после изменения исходников используйте новую версию.

`channels/stable.json` — служебный указатель единственной основной версии. Выбора каналов в AntHub нет.

## Проверка локально (необязательно)

```sh
python -m pip install -r tooling/requirements.txt
python tooling/anthub.py validate .
```

Новости и правила — в `content/`, оформление — в `assets/`. Серверный набор модов устанавливается отдельно вручную.

## Проверка файлов

AntHub получает описание релиза из выбранного GitHub-репозитория и сверяет SHA-256 скачанных файлов. При установке пользователь подтверждает доверие репозиторию. Отдельной подписи автора нет; доверие зависит от доступа к GitHub-репозиторию.

## Один проект — один сервер

Укажите только `server.address`, например `mc-ruslaanchik.ebash.id`. Название, описание и авторов проекта заполнять не нужно. Карточка показывает адрес, MOTD, иконку, число игроков, версию и задержку из стандартного ответа Minecraft-сервера. Сам протокол не передаёт отдельное название сервера: вместо него используется адрес. Недоступный сервер отображается с адресом и статусом недоступности.

Необязательные компоненты изначально включены. Пользователь может отключить их; сохранённый выбор сохраняется при следующих запусках. Конфликтующие альтернативы не включаются одновременно. Для перехода со старого шаблона замените `servers` и `defaultServerId` на `server: {"address": "ваш адрес"}`, удалите блок `project`, обновите tooling и schemas, затем увеличьте `pack.version` и сделайте push.

## Совместимость исходной сборки

Версии модов сохранены. Закреплённый Iris `1.8.14-beta.1+1.21.1-neoforge` объявляет внутри JAR диапазон Minecraft `[1.21,1.21.1)`, исключающий 1.21.1. Перед выпуском проверьте запуск с Iris; при ошибке отключите необязательный компонент или подберите исправленную версию. Валидация проекта не заменяет проверку запуска игры.
